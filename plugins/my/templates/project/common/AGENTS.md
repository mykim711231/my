# {{name}} 작업 규칙

모든 에이전트가 따르는 공통 규칙의 원본이다. 에이전트별 규칙은 `CLAUDE.md`, `GEMINI.md`에 둔다.

## 먼저 읽을 것

작업을 시작할 때마다 아래를 읽는다.

1. [스택](docs/stack.md): 버전, 명령, 경계별 원본, 기준 구현
2. 작업할 명세 `docs/specs/NN-*.md`: `status: approved`인 명세만 구현한다
3. [계약](contracts/README.md) 폴더의 계약 파일
4. 기준 구현 파일(`docs/stack.md`의 "기준 구현")

## 원칙

1. **경계마다 원본은 하나다.** 원본을 고치고 나머지는 다시 생성한다. "생성됨 — 직접 수정 금지"가 붙은 파일은 손으로 고치지 않는다. 무엇이 원본인지는 `docs/stack.md`의 "경계별 원본"을 따른다.
2. **계약을 먼저 정한다.** 두 쪽(서버와 화면, 모듈과 모듈)을 함께 만들 때는 `contracts/`의 계약을 먼저 확정하고 양쪽은 그것만 보고 만든다. 인터페이스를 바꿀 때는 계약부터 고치고 타입 검사가 실패한 곳을 모두 고친다. 같은 구조를 모듈마다 따로 정의하지 않는다.
3. **수직 슬라이스로 만든다.** 기능 하나를 DB부터 API, 화면, 테스트까지 끝내고 동작을 확인한 뒤 다음 기능으로 넘어간다. 이후 기능은 기준 구현의 패턴을 따른다.
4. **요구사항 ID로 추적한다.** `docs/requirements.md`의 `REQ-NN`을 스키마 주석, API, 화면, 테스트에 남긴다.
5. **검증은 도구로 한다.** 다시 생성해서 차이가 나면 실패다. 타입 검사, 계약 테스트, 수용 기준마다 E2E를 둔다. 명령은 `docs/stack.md`의 "명령"에 있다.

## 하지 말 것

- `docs/stack.md`에 없는 의존성을 더하지 않는다. 더해야 하면 `docs/stack.md`와 lock 파일을 함께 고친다.
- 버전, API, 문법을 기억으로 쓰지 않는다. 공식 문서나 레지스트리에서 확인한다.
- 승인되지 않은 명세(`status: draft`)를 구현하지 않는다.
- 테스트를 통과시키려고 테스트나 계약을 약하게 고치지 않는다.

## 문서

- md 파일은 UTF-8(BOM 없음), LF로 쓴다. `#` 제목은 파일당 하나, 제목 단계를 건너뛰지 않는다.
- 링크는 상대 경로와 `/`만 쓰고, 다른 파일의 제목(`#앵커`)으로 링크하지 않는다.
- 명세의 절 제목은 양식(`docs/specs/_template.md`) 그대로 쓴다.
