# 플러그인 평가

모델이 바뀌면 예전 지시문이 필요 없어지거나, 새로 필요해지거나, 오히려 방해가 된다. 지시를 넣은 경우와 뺀 경우를 같은 사례로 돌려 비교해서 판정한다. 검색 결과나 짐작은 판정 근거로 쓰지 않는다.

스크립트: 이 스킬 폴더 기준 `../../scripts/eval.mjs`와 `../../scripts/eval-ablate.mjs`를 Node로 실행한다. 평가 사례는 `../../evals/`에 있다. 플러그인 루트는 이 스킬 폴더 기준 `../..`다.

## 할 일

1. **모델 확인**: 지금 대화의 모델과 `eval.mjs history last`의 지난 평가(날짜, 모델, 점수)를 보여 준다. `eval.mjs cases`로 사례 수와 태그(keyword, trigger, result, stance, overtrigger, mermaid)를 보여 준다. 사례가 없으면 `claude plugin eval init --bare <이름> --eval-dir evals` 양식(`prompt.md` + `graders/*.md`)을 안내하고 멈춘다.
2. **정적 점검**: `eval.mjs lint`의 출력을 그대로 보여 준다. 찾은 항목은 고칠 대상이 아니라 지시 하나 비교의 후보다. 출력 끝의 "직접 확인할 항목"은 지시문을 읽고 해당하는 곳만 덧붙인다.
3. **계획과 승인**: 실행할 내용을 정해 묻는다.
   - 모델: 이 플러그인을 쓰는 모델 모두(haiku, sonnet, opus)가 기본이다. 여러 개를 고를 수 있다. 요청에 "haiku만"처럼 정해 왔으면 그대로 쓴다.
   - 실행 횟수: 1 / 3(기본) / 5. 결과가 실행마다 달라서 1번은 대략 보기용이다.
   - 묶음: 전체(플러그인 유무 비교) / 키워드(`keyword-*`) / 트리거(`trigger-*`) / 결과(`result-*`) / 지시 하나 비교(5단계).
   - 예상 비용: `eval.mjs cost --cases <사례 수> --models <모델> --runs <횟수> --arms <갈래 수>`. 사례 수는 고른 묶음의 수(`cases --tag`로 센다)다. 갈래 수는 전체·결과 2, 키워드·트리거 1(`--ablation none`), 지시 하나 비교는 돌릴 조합 수(원본 포함 2 또는 4)다. 단가를 모르는 모델은 "미측정 — 첫 실행에서 잰다"로 보여 주고, 그 모델의 상한은 사용자에게 받는다.
   - 설정 파일에 저장하지 않는다. "실행 / 바꾸기 / 취소"를 묻는다.
4. **실행**: 승인한 모델마다 따로 실행한다(플러그인 루트에서).
   - `claude plugin eval . --no-publish --threshold 0 --runs <횟수> --model <모델> --judge-model <판정 모델> --max-cost-usd <그 모델 예상 비용> --allow-tools Write --json [--case '<묶음>'] [--ablation none]`
   - `--no-publish`는 리포트가 계정에 올라가지 않게, `--threshold 0`은 점수만 보려고, `--allow-tools Write`는 Mermaid 사례가 파일을 써야 해서 붙인다.
   - 판정 모델은 대상 모델과 다르게 둔다: 대상이 haiku면 sonnet, 그 밖에는 haiku. 같아지면 결과에 "판정 모델 = 대상 모델"을 적는다.
   - 키워드·트리거 묶음에는 `--ablation none`을 붙인다. 플러그인이 없는 갈래에서는 스킬 호출 채점이 점수에 들어가지 않기 때문이다.
   - 비용 상한에 걸려 멈추면 거기까지의 결과만 보고하고, 이어서 돌릴지 묻는다.
5. **지시 하나 비교**(고른 경우만): `eval-ablate.mjs --line "<지시 문장 일부>" --in skills|stance|all` 또는 `--no-stance`(태도 훅 전체를 뺀다)로 복사본을 만든다.
   - 출력된 원본·복사본 명령은 틀로만 쓴다. 4단계 명령의 모델·판정 모델·횟수·상한·`--allow-tools Write`·`--json`·`--case`를 모두 채우고 `--ablation none`으로 원본과 복사본을 같은 사례로 돌린다. 하나라도 빠지면 양쪽이 같은 이유로 실패해 판정이 틀어진다.
   - 태도 규칙(동의로 시작하지 않기 등)은 스킬 본문과 세션 시작 태도 훅 양쪽에 있다. 원본(둘 다), `--in skills`(훅만), `--in stance`(스킬만), `--in all`(둘 다 없음) 네 조합을 비교한다. 출력의 "뺀 줄"에 양쪽 파일이 모두 없으면(문구가 달라 한쪽만 맞으면) 멈추고 알린다.
   - 복사본은 데이터 폴더 아래에 남는다. 원본 플러그인은 건드리지 않는다.
6. **기록 읽기**: 점수만 보지 않는다. 사례 묶음마다 실행 기록을 한두 개 골라, 스킬을 예상과 다른 순서로 읽었는지, 참조를 놓쳤는지, 한 부분에만 기댔는지, 내용을 무시했는지 본다. 점수가 같아도 무시된 내용은 지울 후보로 적는다.
7. **판정**:
   - 전체·결과 묶음(플러그인 유무 비교)은 사례별 넣음/뺌 점수와 차이만 보고한다. 뺌 갈래에는 스킬이 없으므로 지시문 판정에 쓰지 않는다.
   - 키워드·트리거 묶음은 호출률(스킬이 불린 비율)과 오호출(트리거 사례에서 불린 수)을 보고한다.
   - 지시 하나 비교만 아래 표로 판정한다. 세 비율을 따로 보고한다: 호출률, 호출 후 품질(불린 실행의 결과 점수), 전체 성공률(미호출은 실패로 셈).

   | 넣음(원본) | 뺌(복사본) | 판정 |
   |---|---|---|
   | 통과 | 통과 | 필요 없어진 지시 후보 |
   | 통과 | 실패 | 필요한 지시, 그대로 둔다 |
   | 실패 | 실패 | 효과 없음, 문구를 바꾸거나 훅·스크립트 검사로 옮길 후보 |
   | 실패 | 통과 | 방해, 지울 후보 |

   - 양쪽에서 스킬 호출이 관측된 결과만 판정에 쓴다. 한쪽이라도 호출이 관측되지 않았거나 호출률이 떨어졌으면 "보류"로 둔다.
   - 과작동 짝 사례(`overtrigger` 태그)가 넣음 쪽에서 실패하면 그 지시는 "방해" 칸으로 본다.
8. **기록**: "그대로 둔다"가 아닌 판정(필요 없어짐, 효과 없음, 방해)을 받은 지시만 항목마다 `마이 플러그인 문제 {지시 위치와 판정, 근거 점수}`로 문제 목록에 남기도록 안내한다(스킬 하나에 한 항목). 모델마다 `eval.mjs history add --model <모델> --score "<사례 통과/전체, 호출률>" --note "<묶음, 횟수, 판정 요약>"`로 평가 기록을 더한다. 기록하기 전에 "기록 / 건너뛰기"를 묻는다.

질문은 선택지 질문 도구가 있으면 그것으로 묻고, 없으면 번호 목록으로 묻고 번호로 답을 받는다.

채팅 모드(셸·파일 도구가 없거나 이 스킬 폴더 기준 `../../scripts`가 없음)면 이 본문 대신 같은 폴더의 `chat.md`를 따른다. 스크립트가 실행됐다가 실패한 것은 채팅 모드가 아니다.

## 멈출 때

- 비대화형 실행이면 1–3단계(모델, 정적 점검, 계획과 예상 비용)만 보여 주고 "승인 대기 — 대화형에서 다시 실행"을 적는다. 평가는 실행하지 않는다.
- `eval.mjs`나 `eval-ablate.mjs`가 종료 코드 2(`평가 오류:`/`복사본 오류:`)로 끝나면 메시지를 보여 주고 멈춘다. `claude plugin eval`이 없거나 실패하면 오류를 보여 주고 정적 점검 결과만 보고한다.
- 승인한 비용 상한을 넘겨 다시 돌리지 않는다. 더 돌리려면 다시 승인받는다.

## 결과

- 끝: 모델별 점수, 묶음별 보고(유무 차이, 호출률·오호출), 지시 하나 비교의 판정 표(지시 위치, 넣음/뺌, 판정, 보류 이유), 읽은 실행 기록에서 본 점, 정적 점검 후보, 실제 비용, 기록 여부.
- 다른 도구(Codex, Gemini CLI)용 평가 실행은 아직 없다고 적는다.

## 하지 말 것

- 평가 결과로 지시문이나 스킬 원본을 고치지 않는다. 고치는 일은 `마이 플러그인 개선`이 한다.
- 승인 없이 비용이 드는 평가를 실행하지 않는다. `--no-publish`를 빼지 않는다.
- 사례의 채점 기준을 결과에 맞춰 바꾸지 않는다. 기준이 틀렸다고 보이면 문제로 기록한다.
