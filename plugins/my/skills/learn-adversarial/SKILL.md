# 적대적 학습

- 검토 대상을 그대로 받아들이지 않고 검토한 뒤 답한다.
- 목표는 반대가 아니라 정확성이다. 확인된 것은 확인됐다고 말한다.
- 이 스킬을 실행하는 동안 응답 첫 문장을 "맞습니다", "좋은 지적입니다", "문제없습니다" 같은 동의 표현으로 시작하지 않는다.

파일을 만들거나 고치지 마라. 이 스킬은 검토만 한다. 사용자가 노트 추가를 요청한 경우만 예외다(7단계의 노트 생성과, 승인받은 `.gitignore`·`.gitattributes` 한 줄).

스크립트: 이 스킬 폴더 기준 `../../scripts/guard.mjs`와 `../../scripts/learn.mjs`를 Node로 실행한다.

## 할 일

1. **대상 정하기**: `{대상}`이 무엇인지 정한다: 질문·주장·제안·결정안, 파일, 또는 비어 있으면 이 대화의 직전 AI 답변. 대상이 모호하면 무엇을 검토할지 묻는다.
2. **주장 나누기**: 대상을 확인할 수 있는 주장 목록으로 나눈다. 주장마다 근거가 있을 곳(파일:줄, 문서 페이지, 공식 문서)을 적는다.
3. **편집 감시 시작**: `guard.mjs snap <대상 파일과 근거 파일 …>`을 실행하고 출력된 기록 폴더 경로를 기억한다. 넘길 파일이 없으면 인자 없이 실행한다(git 저장소면 커밋 안 된 파일을 기록한다). git 저장소 밖에서 인자 없이 실행했으면 결과에 "감시 대상 없음"을 적는다.
4. **규모 정하기**: 사용자가 말한 규모를 따른다. 말하지 않았으면 주장이 3개 이하이고 근거가 한두 곳이면 경량, 아니면 표준으로 한다.
   - 경량: 직접 근거를 읽어 확인하고 판정을 3줄 이내로 쓴다(결과의 나머지 항목은 한 줄씩 덧붙인다).
   - 표준: 이 대화 안에서 `reviewer.md`의 지침대로 주장을 하나씩 근거와 대조한다. 결과 맨 위에 "분리 검토 아님"을 적는다.
5. **판정 전달**: 주장마다 확인됨·틀림·미확인 중 하나와 근거 위치를 적는다. 지적은 심각도(치명/중요/사소)와 실패하는 구체적 시나리오(입력, 상태, 결과)를 함께 적는다. 결과를 부드럽게 바꾸지 않는다.
   - 학습 자료가 대상이면 그 자료를 먼저 근거로 삼고, 자료 밖에서 찾은 근거는 "자료 외"로 표시한다.
6. **이해도 점검**: 판정 뒤에 "판단을 뒤집을 증거"를 묻는 질문 하나를 한다. 예: "이 전제가 틀리려면 어떤 결과가 나와야 할까?"
7. **노트(요청할 때만)**: 사용자가 노트로 남기라고 하면 `learn.mjs root`로 학습 루트를 보여 주고, 주제와 노트 이름을 확인한 뒤 `learn.mjs new-note <주제> <이름> --title <제목> --source <근거>`로 만들어 판정을 적는다. 루트가 없다고 나오면(종료 코드 3) 제안값을 보여 주고 `마이 플러그인 설정`에서 정하라고 안내한다.
   - 출력에 "원격: 있음"이 나오면(프로젝트 학습 폴더를 처음 만들 때) 먼저 "그대로 커밋 대상으로 둠 / `.gitignore`에 추가 / 이 프로젝트는 중앙 학습 폴더 사용"을 묻는다. 마지막을 고르면 `마이 플러그인 설정`으로 안내하고 노트는 쓰지 않는다.
   - "`*.md eol=lf`: 없음"이 나오고 폴더를 처음 만들면 `.gitattributes`에 `*.md text eol=lf` 한 줄을 추가할지 묻는다.
8. **편집 감시 끝**: `guard.mjs check <기록 폴더>`를 실행한다. 7단계 `new-note` 출력의 `노트:`·`만듦:`·`갱신:` 경로와 승인받아 고친 `.gitignore`·`.gitattributes`는 예상된 변경이다. 위반으로 보고하지 않고 되돌리지 않는다.
   - 그 밖의 파일로 "편집 금지 위반"이 나오면 결과에 그대로 보여 주고(diff 포함), "자동으로 되돌릴 수 없음"이 붙지 않은 파일만 하나씩 되돌릴지 묻는다. 승인한 파일만 `guard.mjs restore <기록 폴더> <파일>`로 되돌린다.
   - "자동으로 되돌릴 수 없음"이 붙은 파일은 직접 확인하라고 알린다.

질문은 선택지 질문 도구가 있으면 그것으로 묻고, 없으면 번호 목록으로 묻고 번호로 답을 받는다.

채팅 모드(셸·파일 도구가 없거나 이 스킬 폴더 기준 `../../scripts`가 없음)면 이 본문 대신 같은 폴더의 `chat.md`를 따른다. 스크립트가 실행됐다가 실패한 것은 채팅 모드가 아니다.

## 멈출 때

- 근거를 읽을 수 없으면 그 주장은 "미확인"으로 두고 이유를 적는다. 추측으로 판정하지 않는다.
- `guard.mjs`가 "확인 오류"로 끝나면 메시지를 보여 주고 결과에 "편집 감시 실패"를 적는다.
- `learn.mjs`가 "학습 오류"로 끝나면 메시지를 보여 주고 노트를 쓰지 않는다. 노트 파일을 직접 만들거나 고치지 않는다.
- 비대화형 실행이면 노트를 쓰거나 파일을 되돌리지 않는다. 판정과 감시 결과만 보여 주고 "승인 대기 — 대화형에서 다시 실행"을 적는다.

## 결과

- 끝: 검토 방식(경량 / 표준·분리 검토 아님), 주장별 판정과 근거 위치, 지적(심각도·시나리오), 이해도 점검 질문, 편집 감시 결과(편집 없음 / 위반과 처리), 노트를 썼으면 경로.

## 하지 말 것

- 참인 주장에 결함을 지어내지 않는다. 사소한 지적을 부풀리지 않는다.
- 검토자의 판정을 사용자 기대에 맞춰 바꾸지 않는다.
