# 설정 동기화

- 방향은 실행할 때마다 `{원본}->{대상}`으로 받는다. 도구 이름은 `claude`, `codex`, `gemini`다. Antigravity CLI는 `codex`·`gemini` 쪽 파일을 그대로 읽으므로 따로 고르지 않는다.
- 범위는 현재 프로젝트(실행한 폴더의 git 루트, 없으면 그 폴더)다. 사용자 홈의 도구 설정 폴더는 다루지 않는다.
- 공통 규칙은 `AGENTS.md`가 원본이다. 대상 규칙 파일(`CLAUDE.md`, `GEMINI.md`)에는 `AGENTS.md` 참조만 만들거나 앞에 더하고, 도구 전용 본문은 그대로 둔다. Codex는 `AGENTS.md`를 직접 읽으므로 규칙 파일을 바꾸지 않는다.
- 스킬 폴더: claude `.claude/skills/`, codex `.agents/skills/`, gemini `.gemini/skills/`.

스크립트: 이 스킬 폴더 기준 `../../scripts/sync.mjs`와 `../../scripts/change-apply.mjs`를 Node로 실행한다. 프로젝트 루트는 실행한 폴더로 정해지므로, 사용자의 작업 폴더에서 스크립트의 절대 경로로 실행한다. 스킬 폴더로 이동해 실행하지 않는다.

## 할 일

1. **방향 확인**: `{원본}`·`{대상}`이 없거나 위 이름이 아니면 번호 목록으로 다시 받는다. 원본과 대상이 같으면 멈춘다.
2. **계획**: `sync.mjs plan <원본> <대상>`을 실행해 출력을 그대로 보여 준다. 출력의 `diff:` 줄은 그대로 실행하지 않고, 스크립트 절대 경로로 `show`를 실행한다.
   - "AGENTS.md가 없다" 보류에 `(후보: …)`가 붙어 있으면 3단계(승격)로 간다. 후보가 없으면(원본이 codex이거나 원본 규칙 파일이 없으면) 승격할 것이 없으니 규칙 파일은 건너뛴다. 승격하지 않으면 규칙 파일은 건너뛰고 스킬만 진행한다.
   - "AGENTS.md를 참조하지 않는다" 알림이 나오면 원본 규칙 파일에 공통 규칙이 섞였을 수 있다고 알리고 "승격 검토(3단계) / 그대로 진행"을 묻는다.
   - 스킬 보류는 이유(SKILL.md가 없음, 스킬 폴더 밖 참조, 없는 파일 참조, 대상에만 있는 파일, 가져오기 순환)와 함께 보여 준다. 보류한 스킬은 이번에 옮기지 않는다. 사용자가 원인을 고친 뒤 다시 실행하면 된다.
   - "바꿀 파일이 없다"면 결과를 보고하고 끝낸다.
3. **승격**(필요할 때만): 원본 규칙 파일의 절을 공통 후보와 도구 전용으로 나눠 보여 주고 후보마다 "공통으로 / 전용으로 남김"을 묻는다. 이미 `AGENTS.md`가 있으면 같은 주제의 규칙끼리 내용이 다른지 보고, 다르면 어느 쪽을 남길지 묻는다.
   - 확정한 내용으로 변경안 JSON을 운영체제 임시 폴더에 쓴다: `{"root": "<2단계 출력의 루트 절대 경로>", "changes": [{"path": "AGENTS.md", "content": "…"}, {"path": "<원본 규칙 파일>", "content": "<참조 줄 + 전용 본문>"}]}`. root는 절대 경로로 쓴다(상대 경로는 변경안 파일 위치 기준으로 풀린다). 참조 줄은 claude `@AGENTS.md`, gemini `@./AGENTS.md`를 줄 머리에 단독으로 쓴다.
   - `change-apply.mjs prepare <변경안 파일>` → `change-apply.mjs show <기록 폴더>`로 diff를 보여 주고 "적용 / 고치기 / 취소"를 묻는다. 승인하면 `change-apply.mjs apply <기록 폴더>`를 실행한 뒤 2단계부터 다시 한다.
4. **승인**: 2단계 출력의 `기록:` 폴더로 `change-apply.mjs show <기록 폴더>`를 실행해 변경 목록과 diff를 보여 주고 "적용 / 취소"를 묻는다.
5. **적용**: 승인하면 `sync.mjs apply <기록 폴더>`를 실행한다.
   - "원본이 계획 당시와 달라" 또는 "승인 당시와 달라진 파일"로 중단되면 목록을 보여 준다. 아무것도 쓰지 않았으니 2단계부터 다시 계획해 새 diff로 승인받는다. 이어서 하던 적용이라 "적용 뒤 달라짐"이 있으면 먼저 "되돌림 / 그대로 둠"을 묻는다.
   - "적용 결과 확인 실패"가 나오면 목록을 보여 주고 "되돌림 / 그대로 둠"을 묻는다.
   - "적용 뒤 검사 실패"(가져오기 순환)가 나오면 순환 경로를 보여 준다. 검사는 루트의 모든 규칙 파일을 보므로, 순환이 이번 변경 파일과 무관하면 그 사실을 알린다. "되돌림 / 고친 뒤 다시 검사(같은 `sync.mjs apply`) / 그대로 둠(미완료로 보고)"을 묻는다.
   - 되돌림은 `change-apply.mjs rollback <기록 폴더>`로 한다. 충돌로 보존한 파일이 있다고 나오면 목록을 보여 주고 상태를 "중단·일부 되돌림"으로 보고한다. 되돌린 뒤 다시 하려면 2단계부터 새로 계획한다.
   - 중간에 끊겼으면 같은 `apply` 명령으로 이어서 한다.

질문은 선택지 질문 도구가 있으면 그것으로 묻고, 없으면 번호 목록으로 묻고 번호로 답을 받는다.

채팅 모드(셸·파일 도구가 없거나 이 스킬 폴더 기준 `../../scripts`가 없음)면 이 본문 대신 같은 폴더의 `chat.md`를 따른다. 스크립트가 실행됐다가 실패한 것은 채팅 모드가 아니다.

## 멈출 때

- `sync.mjs`나 `change-apply.mjs`가 "오류"로 끝나면 메시지를 보여 주고 멈춘다. 파일을 직접 복사하거나 고쳐서 대신하지 않는다.
- 비대화형 실행이면 2단계 계획과 4단계 diff만 보여 주고 "승인 대기 — 대화형에서 다시 실행"을 적는다. 승격·적용은 하지 않는다.

## 결과

- 끝: 방향, 바뀐 규칙 파일, 옮긴 스킬, 바꿀 것 없던 스킬, 보류와 이유, 기록 폴더, 적용 상태(완료 / 승인 대기 / 중단·되돌림).
- 대상이 `codex`이면 한 줄 덧붙인다: Codex에서 이 플러그인의 훅을 쓰려면 새 세션에서 `/hooks`로 my 훅을 검토·신뢰해야 실행된다.
- 대상 도구에서 바뀐 규칙·스킬을 읽으려면 새 세션을 시작하라고 알린다.

## 하지 말 것

- 사용자 홈의 도구 설정 폴더나 인증 파일을 읽거나 옮기지 않는다.
- 승인 없이 쓰거나, 대상에만 있는 파일을 지우지 않는다.
- 공통 규칙 본문을 대상 규칙 파일에 복사하지 않는다(참조만 둔다).
