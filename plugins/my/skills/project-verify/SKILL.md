# 프로젝트 검증

- 검증은 명령을 실행한 결과로만 한다. 실행하지 않은 검사는 "미실행"으로 적는다. 글로 된 판단으로 통과 처리하지 않는다.
- 이 단계는 코드를 고치지 않는다. 고칠 것이 나오면 목록으로 남기고 `마이 프로젝트 {name} 구현`으로 돌린다.
- 파일을 바꾸는 것은 생성 명령이 쓰는 생성물, `docs/trace.md` 재생성, 명세의 검증 결과 절, 승인 후의 `status`뿐이다. 명령 표에서 파일을 고치는 명령(검사 옵션 없는 format 등)은 실행하지 않고 "미실행"으로 적는다.

스크립트: 이 스킬 폴더 기준 `../../scripts/project.mjs`를 Node로 실행한다. 프로젝트 루트는 실행한 폴더의 git 루트로 정해지므로, 사용자의 원래 작업 폴더에서 스크립트의 절대 경로로 실행한다. 스킬 폴더로 이동해 실행하지 않는다.

## 할 일

1. **대상**: `status: approved`인 명세 중 작업 절이 모두 체크된 것을 보여 주고 검증할 것을 고르게 한다. `docs/stack.md`를 읽어 명령 표를 확인한다. git 작업 트리에 커밋 안 된 변경이 있으면 생성물 불일치 검사가 그 변경 때문에 실패하므로, 변경 목록을 보여 주고 "커밋한 뒤 다시 / 그대로 진행(불일치 검사는 미실행)"을 묻는다. 커밋은 사용자가 하거나 `마이 작업 종료`로 한다.
2. **문서 점검**: `project.mjs check`를 실행한다.
3. **도구 검증**: `docs/stack.md` 명령 표에 있는 것을 스택마다 실행하고, 명령과 결과(통과·실패, 실패 요약)를 모은다.
   - 생성물 불일치: 생성 명령을 실행한 뒤 생성물에 차이가 있는지(`git diff --exit-code` 등) 확인한다. 차이가 있으면 실패다. 검사 뒤 생성물 차이는 되돌리지 않고 사용자에게 알린다.
   - DB와 서버 모델: 명령 표의 마이그레이션 검사(자동 생성 diff가 비었는지)를 실행한다.
   - lint, format 검사, 타입 검사, 테스트(계약 테스트 포함), E2E. E2E 줄이 없으면 테스트 줄의 E2E 도구 명령을 E2E로 본다.
   - 명령 표에 없는 검사는 "명령 없음"으로 적는다. 명령을 지어내 실행하지 않는다.
4. **추적표**: `project.mjs trace`로 `docs/trace.md`를 다시 만든다. 명세의 `reqs`마다 명세·DB·계약·코드·테스트 칸에 빈칸(—)이 있는지 보여 준다. 빈칸은 그 경계가 이 요구사항에 필요 없는 경우인지 물어 확인한다.
5. **수용 기준 대조**: 명세의 수용 기준마다 그것을 확인하는 테스트(파일과 이름)를 짝지어 보여 준다. 짝이 없으면 "테스트 없음"으로 표시한다.
6. **독립 검토**: 큰 기능이거나 계약을 바꾼 경우 `마이 적대적 학습 <명세 파일>`로 독립 검토를 하라고 안내한다. 했으면 결과 요약을 받는다. 하지 않았으면 "독립 검토 미실시"로 적는다.
7. **기록**: 명세의 "검증 결과" 절에 날짜, 실행한 명령과 결과, 추적표 빈칸, 수용 기준별 테스트, 독립 검토 여부를 쓴다. `updated`를 오늘 날짜로 바꾼다.
8. **사람 승인**: 결과를 보여 주고 "완료 승인 / 고칠 것 남김 / 보류"를 묻는다. 실패한 검사가 있으면 완료 승인을 선택지에 넣지 않는다.
   - 완료 승인: 명세 `status`를 `done`으로 바꾸고 `updated`를 고친다. `project.mjs check`를 다시 실행한다.
   - 고칠 것 남김: 목록을 검증 결과 절에 적고 `마이 프로젝트 {name} 구현`을 안내한다.
9. **다음 단계**: 남은 명세가 있으면 구현을, 모두 끝났으면 `마이 프로젝트 {name} 배포`를 안내한다.

질문은 선택지 질문 도구가 있으면 그것으로 묻고, 없으면 번호 목록으로 묻고 번호로 답을 받는다.

채팅 모드(셸·파일 도구가 없거나 이 스킬 폴더 기준 `../../scripts`가 없음)면 이 본문 대신 같은 폴더의 `chat.md`를 따른다. 스크립트가 실행됐다가 실패한 것은 채팅 모드가 아니다.

## 멈출 때

- `docs/stack.md`가 없거나 명령 표가 비었으면 실행할 검증 명령을 묻는다. 답이 없으면 문서 점검과 추적표만 하고 나머지는 "미실행"으로 둔다.
- `project.mjs`가 "프로젝트 오류"로 끝나면 메시지를 보여 주고 멈춘다.
- 비대화형 실행이면 1~5단계를 실행해 결과만 보여 주고 명세를 고치지 않는다. 끝에 "승인 대기 — 대화형에서 다시 실행"을 적는다.

## 결과

- 끝: 검증한 명세, 검사별 명령과 결과(통과 / 실패 / 미실행 / 명령 없음), 추적표 빈칸, 수용 기준별 테스트, 독립 검토 여부, 승인 결과와 명세 상태, 다음 단계.

## 하지 말 것

- 실패한 검사를 통과로 적지 않는다. 테스트를 고쳐 통과시키지 않는다.
- 사람 승인 없이 `status: done`을 적지 않는다.
