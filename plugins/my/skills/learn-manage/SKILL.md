# 학습 관리

- 다루는 곳은 학습 루트 하나다. 키워드 끝에 `중앙`이 있으면 `apply`를 뺀 모든 `learn.mjs` 명령에 `--central`을 붙여 중앙 학습 폴더를 다룬다. `{주제}` 끝의 `중앙`은 주제 이름에 넣지 않는다.
- 목록은 읽기만 한다. 파일을 바꾸는 것은 승인받은 통합과, 점검에서 승인받은 `relink` 둘뿐이다. 그 밖의 문제는 보고만 하고 직접 고치지 않는다.
- 노트와 목록 파일은 스크립트로만 바꾼다. 직접 고치지 않는다.

스크립트: 이 스킬 폴더 기준 `../../scripts/learn.mjs`와 `../../scripts/change-apply.mjs`를 Node로 실행한다. 학습 루트는 실행한 폴더의 git 루트로 정해지므로, 사용자의 원래 작업 폴더에서 스크립트의 절대 경로로 실행한다. 스킬 폴더로 이동해 실행하지 않는다.

## 할 일

1. **학습 루트 확인**: `learn.mjs root`를 실행해 학습 루트를 한 줄로 보여 준다. 종료 코드 3이면 제안값을 보여 주고 `마이 플러그인 설정`에서 정하라고 안내하고 멈춘다.
2. 키워드에 따라 아래 하나를 한다.

### 학습 목록

- `learn.mjs topics`를 실행해 주제, 노트 수, 소주제 수, 버전, 최근 학습일을 그대로 보여 준다.

### 학습 점검

- `learn.mjs check`를 실행해 문제를 종류별로 묶어 보여 준다. `참고:` 줄(이전 버전 폴더)과 `건너뜀:` 줄도 그대로 보여 준다.
- 문제마다 고치는 방법을 한 줄로 붙인다.
  - 이동 링크·노트 목록·`INDEX.md` 어긋남: `learn.mjs relink <주제>`.
  - 번호 중복·빈틈, 노트 15개 초과, 노트·소주제 섞임: `마이 학습 통합 <주제>`.
  - 깨진 링크, 절대 경로 링크, 그 밖의 파일 문제: 사용자가 고칠 파일과 줄을 알린다.
- `relink`를 실행할지 주제마다 묻고, 승인한 주제만 실행한 뒤 다시 점검한다.

### 학습 통합 {주제}

1. **살펴보기**: `learn.mjs topics`와 대상 주제의 `index.md`·노트를 읽는다. 이름이나 태그가 비슷한 다른 주제도 함께 읽는다.
2. **안 만들기**: 아래를 찾아 변경안을 만든다.
   - 같은 내용의 노트: 하나로 합친다. 합친 노트의 `sources`는 양쪽을 모두 남긴다. 자료끼리 설명이 다르면 지우지 않고 "자료 간 차이" 절에 함께 적는다.
   - 비슷한 주제: 노트를 한 주제로 옮겨 합친다. 옛 주제의 자료·학습 이력은 대상 주제 `index.md`에 옮겨 적고, 옛 주제의 `index.md`는 지운다.
   - 노트가 15개를 넘은 폴더: 노트를 모두 소주제 폴더(`01-<이름>/`)로 옮긴다. 소주제마다 `index.md`를 둔다(앞머리 `topic`은 상위 주제 이름, `tags`·`updated`, 절 개요·노트·자료·학습 이력).
   - 번호는 옮긴 뒤 폴더마다 `01`부터 빈틈없이 다시 매긴다.
3. **변경안 파일**: 운영체제 임시 폴더에 JSON으로 쓴다. 경로는 학습 루트 기준이다.
   - `{"changes": [{"move": "<옛 경로>", "to": "<새 경로>"}, {"path": "<경로>", "content": "<새 내용>"}, {"path": "<경로>", "delete": true}]}`
   - 앞머리 `subtopic`, 상대 링크, 이동 링크, 목록 파일, `INDEX.md`는 스크립트가 맞춘다. 변경안에는 옮기기, 합친 노트 내용, 지울 노트, 새 `index.md`만 넣는다.
4. **검사**: `learn.mjs stage <변경안 파일>`을 실행한다. "학습 중단"과 새 문제 목록이 나오거나 "옮길 자리에 파일이 있다"·"옮길 파일이 없다" 같은 변경안 오류가 나오면 변경안을 고쳐 다시 실행한다. 통과하면 출력된 `기록:` 폴더를 기억한다.
5. **승인**: `change-apply.mjs show <기록 폴더>`로 변경 목록과 diff를 보여 주고 "적용 / 변경안 고치기 / 취소"를 묻는다.
6. **적용**: 승인하면 `learn.mjs apply <기록 폴더>`를 실행한다.
   - "승인 당시와 달라진 파일"로 중단되면 목록을 보여 준다. "적용 뒤 달라짐"이 없으면 아무것도 쓰이지 않았으니 1단계부터 새 변경안을 만들어 다시 승인받는다. 이어서 하던 적용이라 "적용 뒤 달라짐"이 있으면 먼저 "되돌림 / 그대로 둠"을 묻고, 그다음 새 변경안을 만든다.
   - "적용 결과 확인 실패"가 나오면 목록을 보여 주고 "되돌림 / 그대로 둠"을 묻는다.
   - "적용 뒤 검사 실패"가 나오면 문제를 보여 주고 "변경 목록 밖 파일을 사용자가 고친 뒤 같은 명령으로 다시 검사 / 되돌림"을 묻는다.
   - 되돌림은 `change-apply.mjs rollback <기록 폴더>`로 한다.
   - 중간에 끊겼으면 같은 `apply` 명령으로 이어서 한다.
7. **점검**: `learn.mjs check`로 결과를 확인한다.

질문은 선택지 질문 도구가 있으면 그것으로 묻고, 없으면 번호 목록으로 묻고 번호로 답을 받는다.

채팅 모드(셸·파일 도구가 없거나 이 스킬 폴더 기준 `../../scripts`가 없음)면 이 본문 대신 같은 폴더의 `chat.md`를 따른다. 스크립트가 실행됐다가 실패한 것은 채팅 모드가 아니다.

## 멈출 때

- 위에서 다루지 않은 "오류"로 `learn.mjs`나 `change-apply.mjs`가 끝나면 메시지를 보여 주고 멈춘다. 파일을 직접 옮기거나 고쳐서 대신하지 않는다.
- 다른 적용이 진행 중이라는 잠금 메시지가 나오면 그대로 보여 주고 멈춘다. 잠금 파일을 지우지 않는다.
- 되돌림에서 "보존"한 파일이 나오면 그 파일은 사용자가 확인하도록 목록으로 알린다.
- 비대화형 실행이면 통합은 4단계(검사)까지만 하고 diff를 보여 준 뒤 "승인 대기 — 대화형에서 다시 실행"을 적는다. `relink`도 실행하지 않는다.

## 결과

- 목록: 학습 루트와 주제 목록.
- 점검: 학습 루트, 문제 수와 종류별 목록, 참고·건너뜀, 실행한 `relink`.
- 통합: 기록 폴더, 바뀐 파일 목록, 적용 상태(완료 / 승인 대기 / 중단·되돌림), 점검 결과.

## 하지 말 것

- 이전 버전 폴더를 지우지 않는다.
- 프로젝트 학습 폴더와 중앙 학습 폴더 사이에 노트를 옮기지 않는다. 필요하면 `마이 플러그인 문제`로 기록하라고 안내한다.
- "자료 간 차이"를 한쪽으로 정리해 없애지 않는다.
