# 작업 종료

인계 문서는 검증이 실패해도 반드시 쓴다. `마이 작업 이어서`가 이 문서로 다시 시작한다.

스크립트: 이 스킬 폴더 기준 `../../scripts/work.mjs`를 Node로 실행한다.

## 할 일

1. `work.mjs context`로 프로젝트 상황과 커밋 안 된 변경을 읽는다. 변경 내용은 git diff로 확인한다. git 루트 밖이면 이 대화에서 바꾼 파일로 대신한다.
2. **변경 요약**: 이 대화에서 한 일과 바뀐 파일을 요약한다.
3. **검증**: `docs/stack.md`의 명령표에 있는 lint·타입 검사·테스트 명령을 실행한다. `stack.md`가 없으면 실행할 검증 명령을 묻는다("없음"도 받는다). 실패해도 고치지 않고 결과만 적는다.
4. **커밋 메시지 초안**: 변경을 한 커밋으로 설명하는 메시지를 쓴다. 커밋하지 않는다.
5. **인계 문서**: `work.mjs new-handoff --branch <브랜치> --spec <명세 경로>`를 실행해 양식 파일을 만든다. 명세는 status가 approved인 명세 중 이번 작업의 것 하나다. 명세가 없으면 `--spec`을, git 루트 밖이거나 분리된 HEAD이면 `--branch`를 뺀다. 출력된 경로의 각 절을 채운다.
   - 한 일, 검증 결과(명령과 통과·실패), 커밋 메시지 초안, 다음 할 일(새 대화가 바로 시작할 수 있게 구체적으로), 주의할 것(미완성 부분, 커밋 안 된 변경, 막힌 이유).
   - 다음 할 일은 한 줄에 하나씩 `- ` 목록으로 쓴다.
   - 앞머리와 절 제목은 바꾸지 않는다(`작업 현황`과 `작업 이어서`가 읽는다).
6. **플러그인 불편 사항**: `context` 출력의 "작업 종료 질문"이 켬이면 "이번 작업에서 플러그인 불편 사항이 있었나요?"를 한 줄로 묻는다. 있다고 하면 그 내용으로 `마이 플러그인 문제`를 실행한다. 끔이면 묻지 않는다.

질문은 선택지 질문 도구가 있으면 그것으로 묻고, 없으면 번호 목록으로 묻고 번호로 답을 받는다.

## 멈출 때

- `new-handoff`가 실패하면 오류를 보여 주고 멈춘다. 인계 문서 없이 "종료 완료"라고 하지 않는다.

## 결과

- 끝: 변경 요약, 검증 결과, 커밋 메시지 초안, 인계 문서 경로.
- 커밋은 사용자가 따로 요청할 때만 한다.
