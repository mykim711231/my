# 플러그인 개선 반영

고치는 대상은 원본(`plugin_src`)이다. 설치된 복사본(플러그인 캐시 폴더)은 고치지 마라. 다음 업데이트 때 사라진다.

스크립트: 이 스킬 폴더 기준 `../../scripts/apply.mjs`를 Node로 실행한다. 대기 목록, 항목 보기, 버전 올림, 완료 표시는 이 스크립트로만 한다. 기록 파일과 버전 번호를 직접 고치지 않는다.

## 할 일

1. **대기 목록**: `apply.mjs list`를 실행하고 출력을 그대로 보여 준다.
   - 대기 기록이 없으면 "대기 중인 기록 없음"으로 끝낸다.
   - "고칠 원본"이 없으면 `마이 플러그인 설정`에서 `plugin_src`를 정하라고 안내하고 끝낸다.
   - "커밋 안 된 변경"이 1개 이상이면 알리고, 이어서 할지 묻는다. 아니라고 하면 끝낸다.
   - 비대화형 실행이면 여기서 끝낸다. 아무것도 고치지 않는다.
2. **항목 고르기**: 이번에 반영할 항목을 고르게 한다(여러 개 가능). 고른 항목마다 `apply.mjs show <ID>`로 내용과 상황을 읽는다.
   - 내용이 모호하면 무엇을 바꾸길 원하는지 먼저 묻는다. 추측으로 수정안을 만들지 않는다.
   - 고칠 이유가 없다고 판단되면(이미 고쳐졌거나 기록이 사실과 다름) 근거를 보여 주고, 완료로 표시할지 그대로 둘지 묻는다. 완료로 표시하면 `apply.mjs check`에 나온 현재 버전으로 `done <ID> --version <현재 버전>`을 실행하고, 그 항목은 이후 단계와 `--ids`에서 뺀다. 남은 항목이 없으면 결과로 끝낸다(버전 올림 없음).
3. **기준 읽기**: 고칠 부분에 맞는 plugin-dev 스킬을 먼저 읽는다. 기억에 의존해 고치지 않는다.
   - 스킬(`SKILL.md`) → `skill-development`, 훅 → `hook-development`, 에이전트 → `agent-development`, 설정·데이터 폴더 → `plugin-settings`, 폴더 구조·매니페스트 → `plugin-structure`.
   - 따르는 순서: 공식 문서 > plugin-dev > 기억. 서로 다르면 공식 문서를 따른다.
   - plugin-dev가 없으면 설치를 안내하고, 이번에는 공식 문서만 기준으로 고친다. 결과에 "plugin-dev 미사용"을 적는다.
4. **수정안**: 원본에서 고칠 파일과 diff를 보여 준다. 키워드·스킬 본문 문구, 스크립트, 시험을 함께 고쳐야 하면 모두 보여 준다.
   - 버전 올림 종류를 함께 제안한다: 문구·버그 수정은 `patch`, 키워드·스킬 추가는 `minor`, 키워드 이름 변경·삭제처럼 사용법이 바뀌면 `major`. 여러 항목이면 그중 가장 큰 종류 하나를 쓴다.
5. **승인**: "이대로 고칠까?"를 묻는다. 승인 전에는 원본을 고치지 않는다. 고쳐 달라고 하면 수정안을 다시 만든다. 그만두겠다고 하면 원본을 고치지 않고 끝낸다(버전 올림·완료 표시 없음).
6. **적용과 검증**: 승인된 수정만 적용한 뒤 아래를 모두 돌린다.
   - 1단계 목록의 "고칠 원본" 폴더에서 `node --test "scripts/test/*.test.mjs"`.
   - 플러그인 구조 검증(plugin-dev의 `plugin-validator`, 없으면 `claude plugin validate <플러그인 폴더>`).
   - 바뀐 스킬이 있으면 plugin-dev의 `skill-reviewer`로 검토한다.
   - 검증에서 고칠 것이 나오면 그 수정도 diff를 보여 주고 다시 승인받는다.
7. **버전 올림**: `apply.mjs bump <patch|minor|major> --ids <ID,ID> -- <변경 줄> …`. 변경 줄은 사용자가 알아볼 수 있는 한 줄씩. 버전 올림은 빼먹지 않는다(GitHub 설치는 버전이 같으면 업데이트를 받지 않는다).
8. **확인**: `apply.mjs check`로 매니페스트 버전 일치를 확인한다.
9. **완료 표시**: `apply.mjs done <ID> … --version <새 버전>`. 새 버전은 `bump` 출력 `버전: A → B`의 B다.
10. **커밋 제안**: 바뀐 파일 목록을 보여 주고 커밋과 버전 태그(`v<새 버전>`)를 할지 묻는다. 승인이 있을 때만 한다. push는 사용자가 따로 요청할 때만 한다.

질문은 선택지 질문 도구가 있으면 그것으로 묻고, 없으면 번호 목록으로 묻고 번호로 답을 받는다.

## 멈출 때

- 스크립트가 0이 아닌 코드로 끝나면("개선 오류" 또는 `check`의 "실패:") 메시지를 보여 주고 멈춘다. 버전 번호나 기록 파일을 직접 고쳐 우회하지 않는다.
- 시험이나 구조 검증이 실패하고 고칠 방법이 정해지지 않으면, 버전 올림·완료 표시를 하지 않고 실패 내용과 지금까지 바뀐 파일을 보여 주고 멈춘다.

## 결과

- 끝: 반영한 ID, 바뀐 파일, 검증 결과(통과·실패, plugin-dev 미사용 여부), 새 버전.
- 적용 방법을 설치 방식별로 한 줄씩 안내한다(어느 방식인지는 스크립트가 알려 주지 않으므로 둘 다 적는다).
  - 로컬 등록: 새 세션 또는 플러그인 다시 불러오기.
  - GitHub 설치: push한 뒤 그 PC에서 `claude plugin update my@my`, 그다음 새 세션.
- 남은 대기 기록 수.
