## 2. 공식 가이드

### 2.1 Anthropic — Skill authoring best practices [원문 확인]

- **이미 아는 것은 쓰지 않는다.** "Concise is key" 절의 기본 가정은 모델이 이미 매우 똑똑하다는 것이다. 모델에게 없는 맥락만 더하라고 한다. 같은 PDF 추출 작업을 약 50토큰과 약 150토큰으로 쓴 예를 대비해 보여 준다. → 원칙 1, 2
- **구체성은 작업의 깨지기 쉬움에 맞춘다(degrees of freedom).** 깨지기 쉬운 작업은 "이 스크립트를 그대로 실행하라" 수준으로 좁히고, 열린 작업은 모델에 맡긴다. → 원칙 2, 3
- **결정론적 처리는 스크립트로 한다.** 모델이 직접 쓸 수 있어도 미리 만든 스크립트가 생성 코드보다 믿을 만하고 토큰을 아낀다고 한다. → 원칙 3
- **SKILL.md 본문은 500줄 미만으로 둔다.** 참고 파일은 SKILL.md에서 한 단계로만 연결한다(점진적 공개). → 원칙 5
- **평가로 진행한다.** 평가 주도 개발 순서에 "최소한의 지시를 쓴다"가 한 단계로 있다. → 원칙 6

### 2.2 Anthropic — Effective context engineering for AI agents (2025-09-29) [원문 확인]

- 지도 원리는 "가장 작은 고신호 토큰 집합"이다. 컨텍스트는 수확체감하는 유한 자원이고, 길어지면 회상이 떨어진다(context rot).
- **올바른 고도(right altitude).** 한쪽 실패는 복잡하고 깨지기 쉬운 if-else 로직을 프롬프트에 박는 것이다. 이는 유지보수를 어렵게 한다. 다른 쪽 실패는 너무 모호한 지시다.
- **최소는 짧다는 뜻이 아니다.** 기대 동작을 빠짐없이 설명하는 최소한의 정보다. → 원칙 2의 "결과와 완료 기준"
- **순서:** 최고 모델로 최소 프롬프트를 먼저 시험하고, 관찰된 실패에 따라 지시를 더한다. → 원칙 6
- 예외 상황 목록을 길게 나열하지 말고, 대표 예시를 고른다.

### 2.3 OpenAI — Using GPT-6.2 (latest-model 가이드) [원문 확인]

- 새 모델은 기본적으로 더 간결하므로, 기존 "be concise" 같은 지시를 다시 검토하라고 한다. → 모델이 좋아지면 지시를 줄인다
- 작업 완료에 대해 **모델이 끝내야 할 결과와 사용자 입력이 필요한 결정을 명시하라**고 한다. → 원칙 2의 "결과와 완료 기준", "사람 승인 지점"
- 한계: "최소로 시작하라", "중복 지시를 빼라"는 명시 문구는 없다. 예시 프롬프트도 여러 문단이다. 이 출처는 원칙 2만 뒷받침한다.
- [2차] GPT-5.5/5.6 시기 보도(The Decoder, Decrypt)는 "옛 프롬프트를 옮기지 말고 최소 기준선에서 다시 시작하라"는 OpenAI 안내를 전한다. eval +10–15%, 토큰 −41–66% 수치는 1차 출처에서 확인하지 못했으므로 근거로 쓰지 않는다.

## 3. 실증 연구

### 3.1 Gloaguen 외, Evaluating AGENTS.md (arXiv 2602.11988, v3 2026-09-29) [원문 확인]

저장소 수준 컨텍스트 파일(AGENTS.md 등)이 코딩 에이전트에 도움이 되는지 SWE-bench와 CTXbench(12개 저장소, 138건)로 측정했다. Python만 대상이다.

| 비교 | 성공률 변화 | 유의성 | 출처 위치 |
|---|---|---|---|
| LLM 생성 파일 vs 없음 | SWE-bench −0.5%, CTXbench −2% | 유의하지 않음(p=0.87, 0.37) | §4.2, 표 3 |
| 개발자 작성 파일 vs 없음 | 평균 +2.4% | 유의하지 않음(p=0.21) | §4.2, 표 3 |
| 개발자 작성 vs LLM 생성 | 개발자 작성이 높음 | 유의함(p=0.038) | 표 3 |

| 비용 | 값 | 출처 위치 |
|---|---|---|
| LLM 생성 파일의 단계 수 증가 | +2.45 / +3.92 단계 | §4.2 |
| LLM 생성 파일의 비용 증가 | +20% / +23% (p<0.001%) | §4.2, 표 2 |
| 개발자 작성 파일 | +3.34 단계, 비용 최대 +19% | §4.2 |
| 추론 토큰(LLM 생성, SWE-bench) | GPT-5.2 +22%, GPT-5.1 mini +10% | §4.3, 그림 6 |

- 지시는 잘 따랐다. 파일에 `uv`를 적으면 건당 평균 1.6회 썼고, 적지 않으면 0.01회 미만이었다(§4.3). 즉 쓸데없는 지시도 실제로 행동과 비용을 바꾼다.
- 저장소 개요는 도움이 되지 않았다(§4.3). 개요·테스트·도구 어느 항목도 정확도를 유의하게 바꾸지 않았다. 테스트 절을 빼면 비용이 줄었다(§4.4, 표 7).
- 저자 권고: 컨텍스트 파일에는 코드베이스나 README에 이미 없는 지시(특정 관행, 비기능 요구)만 넣는다. 도입 전에 엄격히 평가한다. LLM 생성 파일은 당분간 빼라고 권한다.
- 주의: 서론의 "개발자 작성이 LLM 생성보다 7% 높다"는 §4.2·표 5와 맞지 않는다(표 5 CTXbench 평균 기준 약 4.2%p). 이 문서는 표의 수치를 쓴다.
- → 원칙 1(설계 문서를 옮기지 않는다), 원칙 6(평가로 확인된 것만 넣는다). 사람이 다듬은 짧은 지시가 생성된 긴 지시보다 낫다는 근거이지만, 사람이 쓴 파일도 성공률을 유의하게 올리지는 못했다.

### 3.2 IFScale — How Many Instructions Can LLMs Follow at Once? (arXiv 2507.11538, 2025-07) [원문 확인, 초록]

- 키워드 포함 지시를 최대 500개까지 늘려 20개 모델을 시험했다.
- 최고 프런티어 모델도 지시 500개에서 정확도 68%였다.
- 지시가 늘 때 성능이 떨어지는 패턴은 모델 크기·추론 능력에 따라 세 가지로 나뉜다.
- 앞쪽 지시를 더 잘 따르는 편향이 있다.
- → 원칙 4(중요한 제약은 앞에), 원칙 2(지시 수 자체가 비용)

### 3.3 Gamage, Omission Constraints Decay While Commission Constraints Persist (arXiv 2604.20911, 2026-04) [원문 확인, 초록]

- 12개 모델, 8개 제공사, 4,416회 시행, 대화 깊이 6단계로 시험했다.
- 금지형("~하지 마라") 준수율은 5턴 73%에서 16턴 33%로 떨어졌다. 요구형("~하라")은 100%를 유지했다.
- 모델별 안전 깊이 전에 제약을 다시 주입하면 회복된다.
- 범위: 시스템 프롬프트의 보안 금지 조항을 다룬 연구다. 일반 스킬 지시에 그대로 일반화할 수는 없다.
- → 원칙 4. 반드시 지켜야 하는 금지는 지시가 아니라 훅·스크립트로 막는다. 남는 금지는 "~하라" 꼴로 바꾼다. 예: "원본을 바로 고치지 마라" → "원본 수정 전에 diff를 보여 주고 승인을 받아라".

### 3.4 Piriyakulkij 외, Subagents vs Agent Skills (arXiv 2609.09233, 2026-09) [원문 확인, 초록]

- 메인 컨텍스트에 불러온 스킬은 작업이 길어질수록 컨텍스트가 쌓여 추론 품질이 떨어지고 깨지기 쉬워진다.
- 스킬 패키지가 입출력 계약이 분명하고 절차 지식을 담고 있으면, 하위 에이전트 실행이 스킬 실행보다 낫다. 대가는 조율에 드는 추가 토큰이다.
- 초록에는 수치가 없다. 본문 수치는 확인하지 않았다.
- 정정: 이전 조사 메모의 "스킬이 하위 에이전트와 같거나 낫다"는 초록과 반대이므로 버린다.
- → 원칙 2·5의 배경. 스킬 본문이 길면 메인 컨텍스트를 키워 긴 작업에서 손해다. 긴 검토(평가, 적대 검토)를 하위 에이전트로 분리한 `plan.md`의 설계와 같은 방향이다.

## 4. 결정론적 강제 패턴 [2차]

실무 자료(Augment Code, agentpatterns.ai)의 공통 결론: 반드시 일어나야 하는 일은 훅, 검사기, CI 관문으로 강제한다. 지시는 그 일이 일어날 확률을 높일 뿐이다. 1차 연구는 아니지만 §2.1(스크립트 선호), §3.3(금지형 지시 감쇠)과 같은 방향이다. → 원칙 3, 4
